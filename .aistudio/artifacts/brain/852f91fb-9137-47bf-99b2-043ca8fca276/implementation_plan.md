# แผนงานแก้ไขปัญหาระบบไม่บันทึกข้อมูลแรงงานคนที่ 2 ขึ้นไป และปรับปรุง UX ให้ใช้งานง่าย

แผนงานนี้จัดทำขึ้นเพื่อแก้ไขปัญหาที่ระบบบันทึกเฉพาะแรงงานคนแรก และข้อมูลแรงงานคนที่ 2 เป็นต้นไปตกหล่น พร้อมทั้งปรับปรุงรูปแบบการกรอกและเพิ่มรายชื่อแรงงานให้กระชับ รวดเร็ว และไม่ซับซ้อน

---

### User Review & Critical Decisions

> [!IMPORTANT]
> **สาเหตุหลักที่ระบบบันทึกเฉพาะแรงงานคนแรก (คนที่ 2 ตกหล่น) ที่ตรวจพบจากการวิเคราะห์เชิงลึก:**
> 1. **การส่งข้อมูลผ่าน Webhook (Google Apps Script):** โค้ดเดิมมีการวนลูปส่ง HTTP Request แยกทีละคนด้วยระยะห่างเพียง 350ms ซึ่ง Google Apps Script ไม่สามารถประมวลผลทันและไม่มีระบบล็อค (LockService) ทำให้คำขอคนที่ 2 เกิดการชนกัน (Concurrency Collision) หรือถูก Google ตัดทิ้ง
> 2. **การดึงข้อมูลกลับเร็วเกินไป (Premature Auto-Sync):** หลังจากกดบันทึก 1.5 วินาที ระบบเรียกฟังก์ชันดึงข้อมูลจากชีตกลับมาทับข้อมูลในเครื่องทันที ซึ่งในขณะนั้นชีตยังบันทึกแถวที่ 2 ไม่เสร็จ ทำให้ข้อมูลคนที่ 2 หายไปจากหน้าจอ
> 3. **ความซับซ้อนของฟอร์ม:** ผู้ใช้ต้องกรอกข้อมูลแยกหลายช่องต่อ 1 คน ทำให้ขั้นตอนเพิ่มคนที่ 2 ดูยุ่งยาก

- **แนวทางแก้ไขที่เลือก:**
  - **ส่งข้อมูลแบบรวมชุดเดียว (Single Atomic Batch):** ส่งแถวแรงงานทุกคนรวมใน 1 ครั้งผ่าน Payload เดียว (`rows: rowsData`) เพื่อให้ Google Apps Script บันทึกครบทุกแถวในคราวเดียวอย่างแม่นยำ 100%
  - **ปรับโค้ด Google Apps Script ในระบบให้มี `LockService`:** ป้องกันการเขียนทับหรือข้อมูลชนกันเมื่อมีการบันทึกพร้อมกัน
  - **ปรับปรุงกระบวนการ Auto-Sync:** รอให้การบันทึกสำเร็จจริง และใช้การผสานข้อมูล (Merge) แทนการเขียนทับ State ในเครื่องทันที
  - **ลดความซับซ้อนของฟอร์มเพิ่มแรงงาน:** ให้แรงงานคนที่ 2 สืบทอดสัญชาติและประเภทแรงงานจากคนแรกโดยอัตโนมัติ เหลือเพียงกรอกเลข 13 หลักและชื่อ-นามสกุลเท่านั้น พร้อมปุ่มเลือกจำนวนคนด่วน (+/-)

### 1. ภาพรวมและเป้าหมาย (Overview & Core Concept)

- **เป้าหมาย:** รับประกันว่าข้อมูลแรงงานทุกคน (ไม่ว่าจะเป็น 1 คน, 2 คน หรือหลายคน) จะถูกบันทึกลงทั้งฐานข้อมูลในเครื่อง (LocalStorage) และ Google Sheets ครบถ้วนทุกรายชื่อ พร้อมทั้งลดขั้นตอนในการเพิ่มแรงงานคนที่ 2 ให้ง่ายขึ้น
- **กลุ่มผู้ใช้งาน:** เจ้าหน้าที่สำนักงานจัดหางานที่ต้องบันทึกข้อมูลการจัดเก็บเงินประกันของแรงงานต่างด้าวอย่างต่อเนื่องและรวดเร็ว

```
┌─────────────────────────────────────────────────────────────┐
│               การบันทึกข้อมูลแรงงานหลายคน                   │
└────────────────────────────────┬────────────────────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
      [ ส่วนติดต่อผู้ใช้ (UX) ]        [ ส่วนบันทึกฐานข้อมูล ]
      - ตัวเลือกจำนวนคนแบบด่วน (+/-)   - ส่ง Atomic Batch (1 Request)
      - ดึงสัญชาติ/ประเภทอัตโนมัติ      - Apps Script พร้อม LockService
      - กรอกเพียงเลข 13 หลัก + ชื่อ     - ป้องกัน State Overwrite ในเครื่อง
```

### 2. การปรับปรุงประสบการณ์ผู้ใช้ (UX & Form Simplification)

1. **ระบบเพิ่มจำนวนแรงงานที่เรียบง่ายขึ้น (Streamlined Worker Addition):**
   - ด้านบนของส่วนกรอกแรงงาน จะมีตัวนับจำนวนแรงงานแบบปุ่มบวก-ลบ (+ / -) ที่กดเพิ่มหรือลดได้ทันที
   - เมื่อกดเพิ่มแรงงานคนที่ 2:
     - ค่าเริ่มต้นของ **สัญชาติ** และ **ประเภทแรงงาน** จะถูกคัดลอกจากแรงงานคนแรกอัตโนมัติ (เจ้าหน้าที่ไม่ต้องเลือกซ้ำ ยกเว้นต้องการแก้ไข)
     - โฟกัสเคอร์เซอร์จะกระโดดไปที่ช่อง **เลขประจำตัว 13 หลัก** ของคนที่ 2 ทันที
     - ตัวพิมพ์ภาษาอังกฤษของชื่อจะแปลงเป็นตัวพิมพ์ใหญ่อัตโนมัติ (A-Z)
2. **สรุปความชัดเจนก่อนบันทึก (Pre-Save Modal):**
   - หน้าต่างสรุปก่อนบันทึกจะแสดงตารางรายชื่อแรงงานทุกคนอย่างชัดเจน พร้อมคำนวณยอดเงินรวม เช่น 2 คน = 2,000 บาท เพื่อความมั่นใจก่อนกดบันทึกจริง
3. **การแจ้งเตือนสถานะการบันทึกที่โปร่งใส:**
   - แสดงข้อความยืนยันชัดเจน เช่น *"บันทึกและส่งข้อมูลแรงงาน 2 คนลง Google Sheet เรียบร้อยแล้ว (แถวที่ 5-6)"*

### 3. การปรับปรุงสถาปัตยกรรมทางเทคนิค (Technical Architecture)

```
┌─────────────────────────┐
│ DepositForm (Client UI) │
│ - เพิ่มคนที่ 2 (Auto-fill)│
└────────────┬────────────┘
             │ onSave(record with workers[])
             ▼
┌─────────────────────────┐
│        App.tsx          │
│ - บันทึกลง LocalState   │
│ - เรียกส่ง Google Sheet │
└────────────┬────────────┘
             │
             ├──────────────────────────────────────────────────┐
             ▼                                                  ▼
┌───────────────────────────┐                      ┌───────────────────────────┐
│ appendRecordViaAppsScript │                      │    appendRecordToSheet    │
│ (กรณีใช้ Webhook)         │                      │    (กรณีใช้ OAuth Token)  │
│ - ส่ง 1 Payload รวมทุกแถว  │                      │ - values:append ทั้งหมด   │
│   rows: [row1, row2, ...] │                      │   ในครั้งเดียว            │
└────────────┬──────────────┘                      └─────────────┬─────────────┘
             │                                                   │
             ▼                                                   ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│                              Google Sheets                                   │
│                      (บันทึกแถวแรงงานครบทุกคน 100%)                          │
└──────────────────────────────────────────────────────────────────────────────┘
```

1. **แก้ไข `appendRecordViaAppsScript` ใน `src/services/googleSheets.ts`:**
   - ยกเลิกการวนลูปส่งแบบแยก Request ถี่ๆ (350ms) ซึ่งเป็นสาเหตุให้คำขอที่ 2 ล้มเหลว
   - ปรับให้ส่งข้อมูลแบบชุดเดียว (Single Atomic Payload):
     ```typescript
     {
       action: 'append_row',
       record: record,
       rows: rowsData, // มีครบทุกแถวทั้งคนที่ 1 และคนที่ 2
       row: rowsData[0] // fallback สำหรับสคริปต์แบบเดิม
     }
     ```
2. **ปรับปรุงโค้ด Google Apps Script ใน `src/components/GoogleSheetsBar.tsx`:**
   - เพิ่ม `LockService.getScriptLock()` เพื่อจัดคิวการบันทึก ป้องกันปัญหาข้อมูลชนกัน
   - เพิ่มฟังก์ชันรองรับการอ่าน `data.rows` ทั้งชุดและบันทึกรวดเดียวครบทุกแถว
3. **แก้ไขจังหวะ Auto-Pull ใน `src/App.tsx`:**
   - ปรับไม่ให้ดึงข้อมูลมาทับทันทีที่ 1.5 วินาที แต่ให้ผสาน (Merge) ข้อมูล หรือรอให้ฝั่ง Sheet บันทึกเสร็จเรียบร้อยก่อน เพื่อป้องกันการลบข้อมูลของคนที่ 2 ออกจากจอภาพ

### 4. แผนขั้นตอนการดำเนินการ (Execution Steps)

1. **ขั้นตอนที่ 1:** ปรับปรุง `appendRecordViaAppsScript` ให้ส่งข้อมูลแรงงานทุกคนใน Request เดียว ป้องกันเครือข่ายหลุดและ Race Condition
2. **ขั้นตอนที่ 2:** ปรับโค้ดต้นแบบ Google Apps Script ให้มีระบบ LockService และรองรับการบันทึกหลายแถวพร้อมกัน
3. **ขั้นตอนที่ 3:** ปรับปรุงฟอร์มใน `DepositForm.tsx` ให้มีตัวช่วยกรอกคนที่ 2 ได้สะดวกรวดเร็ว (Auto-fill สัญชาติ/ประเภท, โฟกัสอัตโนมัติ)
4. **ขั้นตอนที่ 4:** ปรับกลไก Auto-sync ใน `App.tsx` ไม่ให้เขียนทับข้อมูลใหม่ที่เพิ่งบันทึก
5. **ขั้นตอนที่ 5:** ทำการ Compile ตรวจสอบความถูกต้อง และทดสอบการบันทึกแรงงาน 2 คนขึ้นไป
